# reply-reader — read a Pi / Gentle Shell reply aloud, on request

A Pi package (`pi-reply-reader`), separate from `pi-reply-thread` (its S6), that reads a reply aloud
with local text-to-speech after cleaning its Markdown for listening. Nothing plays by itself.

## Specs

- S1 — On request only. Owner (verbatim, pi-reply-thread L3): "que el lector NO se ejecute automáticamente, a menos que se lo diga, algo como defautl=false, esto porque puede que los audios se pisen" → `autoRead` false by default; `/read` reads the latest reply, `/read P12.R1` a given one; a new reading stops the one playing.
- S2 — Markdown cleaned for speech. Owner (verbatim, L3): "como las respuestas son en markdown algunas cosas se leen raro, esto ya lo vi, algo como "asterisco asterisco negrilla asterisco asterisco", o también el formato de las tablas: "or col 1 or col 2 or col 3 or", o "guión" o "guión bajo" muchas veces. también está la parte del código: "comilla simpmle" muchas veces, así con las salidas del markdown." → deterministic cleanup (no model): emphasis, headings, bullets, tables, inline code, code blocks, links. A fenced code block is announced, not read: "Bloque de código." (L3).
- S3 — Local engine. Decision (pi-reply-thread L64): "sherpa-onnx + Piper (recomendado)": local, no API key, optional pinned download after a confirm (the gsh dictation pattern). Voice: es_MX-claude-high (L4). If the machine where Pi runs already has piper and that voice, reuse them instead of downloading (L5, owner chose "Reusar un piper local si existe").
- S4 — Where it sounds. Owner (verbatim, L64): "yo iria por la segunda opción, esto ya que normalmente uso el hs como "servidor" y la desktop como "cliente" de ssh, pero la duda es qué tanto será así, puede que el dia de mañana quiera usar el hs como cliente mismo o cambiar a otro dispositivo para que sea el nuevo cliente en lugar de la desktop, entiendes?" → synthesis runs where Pi runs (L5). Audio goes to one of a list of named outputs, such as `hs` (the local default sink) and `desktop` (li-desktop's PipeWire-Pulse over the LAN, accepting only the hs). The first `/read` of a session asks which one, and `/read-output` switches later (L6-L8). There is no SSH detection, because under herdr the SSH env is stale (L7). A new client means adding an output, not changing the package. Termux comes later (L7).
