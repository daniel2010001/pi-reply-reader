# reply-reader — read a Pi / Gentle Shell reply aloud, on request

A Pi package (`pi-reply-reader`), separate from `pi-reply-thread` (its S6), that reads a reply aloud
with local text-to-speech after cleaning its Markdown for listening. Nothing plays by itself.

## Specs

- S1 — On request only. Owner (verbatim, pi-reply-thread L3): "que el lector NO se ejecute automáticamente, a menos que se lo diga, algo como defautl=false, esto porque puede que los audios se pisen" → `autoRead` false by default; `/read` reads the latest reply, `/read P12.R1` a given one; a new reading stops the one playing. Stop (L48, owner: "también quisiera saber cómo estamos haciendo esto del stop, lo tenemos?"; choice "Sí, agregar /read-stop"): besides Esc and a new reading, `/read-stop` stops the reading playing and says "Reading stopped."; with nothing playing it says "Nothing is being read." and changes nothing. One reading per machine (L50, owner: "nuevo "bug" encontrado, dos audios se "solapan", cuando se corrió el audio de ejemplo se seguía corriendo el read Readme que lo ejecuté antes"; choice "La última gana en todo el equipo (recomendado)"): a new reading from any Pi session or process stops the one playing elsewhere, and `/read-stop` also stops a reading started by another session; coordinated through a file under `$XDG_RUNTIME_DIR/pi-reply-reader/`. A stale entry (its process gone) is ignored. The session whose reading was stopped by another clears its status quietly, with no error message.
- S2 — Markdown cleaned for speech. Owner (verbatim, L3): "como las respuestas son en markdown algunas cosas se leen raro, esto ya lo vi, algo como "asterisco asterisco negrilla asterisco asterisco", o también el formato de las tablas: "or col 1 or col 2 or col 3 or", o "guión" o "guión bajo" muchas veces. también está la parte del código: "comilla simpmle" muchas veces, así con las salidas del markdown." → deterministic cleanup (no model): emphasis, headings, bullets, tables, inline code, code blocks, links. A fenced code block is announced, not read: "Bloque de código." (L3). IDs and symbols are made speakable (L25-L27, T10): every engine stumbled on "P11.R1.Q1 a Q5", "gsh" and "s llena R: Sí. o → Sí.". (a) Dotted reply IDs `P11.R1` / `P11.R1.Q1` become "P 11, R 1" / "P 11, R 1, Q 1". (b) Symbols become words: → ⇒ ➜ "a", ← "desde", ≈ "aproximadamente", ≠ "distinto de", ≥ "mayor o igual a", ≤ "menor o igual a", ± "más o menos", × between numbers "por", & "y". (c) Emoji and pictographs are dropped. (d) Paths and branches (a token with no spaces, with "/" between letters or starting with `~/`, `./` or `/`) are spoken as words: separators, a leading `~` or `.`, and inner `-`/`_` become spaces, and a final `name.ext` becomes "name punto ext". So `~/.gentle-shell/agent/AGENTS.md` becomes "gentle shell agent AGENTS punto md", `feat/pending-central` becomes "feat pending central", and `/replies` becomes "replies". Numbers like `1/2` are left as they are. Rule (d) is replaced by per-class readings (L33-L34, T11). Each technical token (a run with no spaces, in prose or inline code) is classified once, in this order:
  (e1) URL: only the host, as before.
  (e2) Branch: a token after the word "rama" or "branch" is spoken as its name words only ("la rama `feat/pending-central`" → "la rama feat pending central"). Elsewhere, a token starting with `feat/`, `fix/`, `docs/`, `chore/`, `refactor/`, `test/`, `release/`, `origin/` or `upstream/` becomes "la rama …" ("`origin/main`" → "la rama origin main").
  (e3) Path with a line: `path:N` becomes the file reading plus ", línea N" ("`src/speech-text.ts:42`" → "speech text punto ts, en src, línea 42").
  (e4) Path: a token with `/` between segments, or starting with `~/`, `./`, `../` or `/` plus at least two segments. It is read as the last part plus its folder ("Archivo y carpeta donde está", L34). A file (last part with a letter-only extension) becomes "<name> punto <ext>, en <folder>" ("`~/.gentle-shell/agent/AGENTS.md`" → "AGENTS punto md, en agent"). A folder becomes "la carpeta <name>, en <folder>" ("`/tmp/reply-reader-bakeoff/wav/hs/`" → "la carpeta hs, en wav"). A path with one part under `~/` or `/` has no folder ("`~/.gentle-shell`" → "la carpeta gentle shell"). In names, a leading `.`, `-` and `_` become spaces.
  (e5) Alternatives: exactly two letter-only parts with no leading marker, no extension and no branch prefix become "X o Y" ("`light/dark`" → "light o dark"). Short pairs like `y/o` and `km/h` stay as before.
  (e6) Command: a single segment `/word` becomes "el comando word" ("Corré `/reload`" → "Corré el comando reload").
  (e7) File name: a bare `name.ext` (letter-only extension, the name has a letter, no `/`) becomes "name punto ext" ("`README.md`" → "README punto md"). Versions, numbers and URL hosts are untouched.
  (f1) Approximations: `~` right before a number becomes "aproximadamente" ("~1,2 s" → "aproximadamente 1,2 segundos"; changed from "unos" in L40 because "unos" breaks gender agreement, as in "las unos 400 líneas"). Other `~` stay as rules (d)/(e4) read them.
  (f2) Units right after a number (optional space, then a non-letter): `s` → "segundos" (every unit is singular after exactly 1: "1 segundo", "1 megabyte", "1 decibel"), `ms` → "milisegundos", `min` → "minutos", `KB`/`MB`/`GB` → "kilobytes"/"megabytes"/"gigabytes", `%` → "por ciento", `dB`/`dBFS` → "decibeles".
  (f3) Inline code holding a single punctuation mark is spoken by name: `.` "punto", `,` "coma", `;` "punto y coma", `:` "dos puntos", `!` "signo de exclamación", `?` "signo de pregunta", `~` "virgulilla", `/` "barra", `-` "guion", `_` "guion bajo", `*` "asterisco", `#` "numeral", `|` "barra vertical".
  (f4) A line made entirely of emphasis (`**Qué cambió**`, `*Nota*`, `__X__`) is read like a heading: closed as a sentence and followed by a section break.
  (f5) Headings and bold-only lines are always followed by a section break (a blank line in the cleaned text), even when the next line follows directly.
  (g1) An ordered list marker at line start (`1.`, `2)`), or a number and period starting a numbered heading or bold line (`## 1. Estado`, `**2. Engram**`), becomes "1:" so the player does not cut after "1." and read the number alone (L43).
  (g2) When a rule inserts an article, a preceding contraction is undone to match it: "del" + "el comando" → "del comando", "al" + "el comando" → "al comando", "del" + "la rama"/"la carpeta" → "de la …", "al" + "la …" → "a la …", "del"/"al" + "un commit" → "de un commit"/"a un commit" ("Después del `/reload`" → "Después del comando reload", L43).
  (g3) The heading or bold-only line "Needs your decision" (with or without a final colon; the closing section every reply here uses) is spoken as "Decisiones pendientes" (L43).
  (h1) Numbers with dots (L48, owner: "el número 1.1, se debería leer uno punto uno, o con coma si lo prefieres, pero no se lee de esta forma, sino se lee o "uno    uno" (con un espacio entre los números), o solo un uno"; choice "uno punto uno"): a run of digit groups joined by single dots is read with "punto": "1.1" → "1 punto 1", "0.8.0" → "0 punto 8 punto 0". A trailing period after such a number that ends a numbered heading or item ("## 5.2. Título") becomes ":" as in (g1): "5 punto 2: Título". Exceptions: Spanish thousands (1-3 digits, then one or more groups of exactly 3 digits, first group not 0, such as "2.750" or "1.500.000") stay as they are; reply IDs (a), URLs, file names, paths and IP addresses keep their own readings; a number ending a sentence ("son 1.1.") keeps its final period.
  (e8) Commit hash: 7-40 hex characters with at least one digit and one letter. Right after the word "commit" or "commits" it is dropped ("commit `0e8bb95`" → "commit"); elsewhere it becomes "un commit".
  (j1) Numbers in words (L106, owner, verbatim: "la 1 y 3 suenan mal, y las 2 y 4 suenan bien, por qué pasa esto? creo que la cosa es que los números se leen en otro idioma, o es lo que supongo, qué está pasando? esto pasará cuando el idioma sea otro, por ejemplo ingles?"; choices "Por la palabra siguiente (recomendado)" and "Dígito por dígito (recomendado)"): Supertonic mispronounces digits ("51" sounds like "zinsueuno"), so every run of digits left in the spoken text, after all other rules, becomes words in the text's language (S7): "51" → "cincuenta y uno" ("fifty one"; no hyphens), "2026" → "dos mil veintiséis", Spanish thousands "11.457" → "once mil cuatrocientos cincuenta y siete", decimals "1,2" → "uno coma dos", and the digit groups of readings that already use "punto" one by one ("1 punto 4" → "uno punto cuatro", versions and IP addresses alike), a leading minus before a number "menos" ("minus"). Agreement (Spanish only): a number ending in 1 becomes "un" ("veintiún", "un") before a word ("1 segundo" → "un segundo", "21 días" → "veintiún días"), and "una"/"veintiuna"/"… y una" before a word on a list of frequent feminine nouns (singular and plural: línea, respuesta, pregunta, sesión, tarea, vez, hora, semana, página, carpeta, rama, prueba, versión, lectura, voz, opción, regla, palabra, cosa, parte, persona, máquina, salida, entrada; tunable): "1 respuesta" → "una respuesta", "21 líneas" → "veintiuna líneas". It stays "uno" before punctuation, at the end, and before a function word ("de 1 a 5" → "de uno a cinco", "1 de 3" → "uno de tres"; the list is in the phrasebook: a, de, del, al, y, e, o, u, ni, en, por, para, con, sin, entre, hasta, desde, sobre, contra, según, que, es, son, más, menos, coma, punto). Digits stay as written only inside URLs/hosts and inside technical tokens no class claimed (the S12 diagnostics); digits glued to letters are separated ("Q5" → "Q cinco", "v2.0.1" → "v dos punto cero punto uno"); a dot left between digit groups reads "punto"; in English a comma before three-digit groups is a thousands separator ("1,234"), any other comma between digits reads "coma"/"comma" (L107). Long numbers: a run of more than 9 digits, or one of two or more digits starting with 0 ("007", "5551234567"), is read digit by digit ("cero cero siete").
  (k1) Hundreds agree (L112): with a feminine listed noun after the number (directly or after "mil"), hundreds take the feminine: "400 líneas" → "cuatrocientas líneas", "500 respuestas" → "quinientas respuestas", "221 líneas" → "doscientas veintiuna líneas", "200.000 líneas" → "doscientas mil líneas". Spanish only.
  (k2) Times (L112, choice "\"veintiuno cero dos\" (recomendado)"): a standalone `H:MM` or `HH:MM` (hour 0-23, minutes 00-59), optionally `:SS`, reads like a digital clock, hour without its leading zero, minutes 01-09 as "cero N": "`21:02`" → "veintiuno cero dos", "`07:30`" → "siete treinta", "`21:02:15`" → "veintiuno cero dos quince"; minutes 00 read "en punto" ("o'clock"): "`07:00`" → "siete en punto" (my call). English: "seven thirty". Anything else with `:` between digits (`4.5:1`, `25:61`) keeps today's reading.
  (k3) Dates (L112, choice "\"27 de octubre de 2026\" (recomendado)"): only with a year, so `1/2` stays a fraction: `YYYY-MM-DD` and `DD/MM/YYYY` (day first in both languages) with a valid month and day read "27 de octubre de 2026" ("October 27, 2026"), numbers in words by (j1): "veintisiete de octubre de dos mil veintiséis". Day 1 reads "uno de …" ("1 de enero" → "uno de enero"). Dates without a year and invalid ones keep today's reading.
  (k4) Globs (L112, choice "\"cualquier …\" (recomendado)"): a token with `*` that no other class claims: a leading `*` reads "cualquier" plus the rest read as usual ("`*.hs.lan`" → "cualquier hs punto lan"), a trailing `/*` reads "todo lo de" plus the folder ("`bin/*`" → "todo lo de bin"), and any other `*` reads "algo" ("`lab-*`" → "lab algo", "`TEST_CKAN_*`" → "TEST CKAN algo"; my call). English: "any", "everything in", "something".
  (k5) Tags and angle-bracket wrappers (L112, rewritten by L118). A name is letters, digits and `-`, starting with a letter, HTML or not (`<command>`, `<thinking>`, `<my-widget>`). A pair `<name>…</name>` in the same text reads the name, a colon pause and the content; the closing tag is silent: "`<command>ls -la</command>`" → "command: " then `ls -la` read by the existing rules; "`<thinking>dudo</thinking>`" → "thinking: dudo". A lone `<name>` with no matching closing tag (placeholders such as `<archivo>`, `<path>`, `<id>`, or `<iframe>` in prose) reads only the name: "`reply-reader <archivo>`" → "reply-reader archivo" (the hyphenated word keeps its existing reading); "Usá un `<iframe>`" → "Usá un iframe". A lone closing `</name>` or a self-closing `<name/>` reads "la etiqueta name" ("the name tag"; only the name right after "etiqueta"/"tag"). `<< text >>` (a format models use, not a tag) reads like quotes: the `<<` and `>>` are silent and the text inside is read with a short pause before and after: "`<< esto no es un tag >>`" → "esto no es un tag".
  (i1) Bare folders and dot files in paths (L100, choice "Como las demás rutas (recomendado)"): a relative token of one part ending in `/` is a folder like (e4) ("`src/`" → "la carpeta src", "the folder src"; right after "carpeta"/"folder" only the name). A path whose last part starts with a dot is read like any other (e4) file or folder ("`ckan-docker/.prettierrc.json`" → "prettierrc punto json, en ckan docker"; the most frequent real case is an example env file under ckan-docker). A dot-leading last part with no extension in a path of two or more parts is a file named without the dot (L102; a one-part `~/.name` keeps (e4)'s folder reading, since in real replies those are folders about 40 times to 3, L103): "`ckan-docker/.gitignore`" → "gitignore, en ckan docker", and the same for an env file under ckan-docker.
  (i2) Issue and PR numbers (L100, choice "\"número 43\" (recomendado)"): a standalone `#` followed by digits becomes "número N" ("number N" in English): "el PR #43" → "el PR número 43". Trailing punctuation stays. Headings are not affected.
  (i3) Key combinations (L100, choice "\"Alt más R\" (recomendado)"): modifier names (Ctrl, Control, Alt, Shift, Cmd, Command, Super, Meta, Win, Option, Fn; any case) joined by `+` to a key (one character, a key name such as Enter, Tab, Esc, Space, Delete, Backspace, Up, Down, Left, Right, Home, End, or F1-F12) are read with "más" ("plus"); `Ctrl` reads "Control": "`Ctrl+Shift+P`" → "Control más Shift más P", "Alt+R" → "Alt más R".
  (i4) Minimum versions (L100, choice "\"v1 o superior\" (recomendado)"): a version (`v` optional, then digit groups joined by dots) followed by `+` becomes "<version> o superior" ("or later"), its dots read as in (h1): "`v1+`" → "v1 o superior", "`v2.0+`" → "v2 punto 0 o superior", "1.4+" → "1 punto 4 o superior". A whole number with no `v` and no dot followed by `+` is a count (L102, owner: "estaba pensando en \"100 o más\" o algo así"): "N o más" ("N or more"): "`100+`" → "100 o más", "300+ líneas" → "300 o más líneas", "6.000+" → "6.000 o más".
- S3 — Fast mode, local engine (rewritten in L21; the Piper choice of L4-L5 was made, in the owner's words, "sin estar informado", L13). Supertonic 3 on current sherpa-onnx-node (v2, GPL-free) runs where Pi runs: local, no API key, a pinned download after a confirm. Default voice male, sid 6 ("por lo pronto me gusta más la masquilina", L20). The female voice sid 0 ships in the same model and is selectable ("si lo publicamos creo que sería bien tener ambos", L20). Text is synthesized sentence by sentence, so audio starts in about 1-2 s (hs-cpu.md). Pauses are ours, not the model's (L36-L37): text splits only after `. ! ? …` and at line breaks (never at `:` or `;`), each fragment's own leading and trailing silence is trimmed, and a fixed pause follows each fragment: 0.25 s between sentences on a line, 0.4 s at a line break (list items, table rows), 0.6 s at a blank line (after a title, between paragraphs). The owner chose "Sí, con pausas cortas (recomendado)". Pause ladder (L39), so each mark sounds different: commas, `;` and `:` keep the voice's own short pause (no split); a period followed by more text on the same line (punto seguido) gets 0.35 s; a line break (punto aparte, list item, table row) 0.5 s; a section break (blank line, heading, bold-only line) 0.75 s. These values are tunable by ear. Synthesis runs ahead of playback (L71): while a sentence plays, the next one is already being synthesized, without waiting for the player to drain, and each pause is written right after its own sentence, so a slow synthesis never lengthens a pause it could have overlapped; at most a small bounded number of synthesized sentences wait in memory, and stop, Esc, `/read-stop`, a newer reading and a dead player still end everything at once. Speed (L43): owner, verbatim: "lo noto un poco más lento, no por las pausas, sino por el audio o la lectura en general" → the voice speed (Supertonic `speed`, 1.0 today) is chosen by ear from samples at 1.0, 1.1, 1.2 and 1.3. After the samples (L46), owner, verbatim: "la 1.1 podrías repetirla? descartado la 1.3, muy rápido, o qué te parece si lo dejamos como "configurable"? se puede hacer esto? así los que la usen pueden configurarlo como ellos prefieran, o muy rápido o muy lento o intermedio, qué dices?" → speed is configurable. Default 1.1. `/read-speed <n>` sets any number from 0.5 to 2.0 (a comma decimal such as `1,15` is accepted too) and confirms with "Readings will use speed 1.15."; `/read-speed` with no argument offers a selector with 0.8, 0.9, 1.0, 1.1, 1.2, 1.3 and 1.5. Anything else warns "Speed must be a number from 0.5 to 2.0." and changes nothing, including the saved file. The choice is saved in `$XDG_CONFIG_HOME/pi-reply-reader/settings.json` (`~/.config/…` when unset) as `{ "speed": 1.15 }`, keeping any other keys, and every later session and reading uses it; a reading already playing keeps its speed. A missing file means the default; an unreadable or invalid file (or speed out of range) warns once per session and uses the default. If saving fails, the speed still applies to this session and a warning says it was not saved. Only the voice speed changes; our pauses (the ladder) stay as they are. Piper, piper-tts reuse, sherpa 1.13.8 and espeak-ng are dropped.
- S7 — Language of the added words. Owner (verbatim, L48): "algunas cosas están en español, mientras que el texto del rEADME está en ingles, no digo que está mal, sino que es algo raro, se lee correctamente en ingles, pero las partes que tocamos, como "el comando", "bloque de código", etc. se leen en español, quisas esto sea un poco raro, qué dices?" → choice "Detectar el idioma del texto (recomendado)": the reply or file as a whole is classified as English or Spanish from its own words (deterministic, no model); for English text every word the cleanup adds is English ("Code block.", "the command reload", "the folder hs, in wav", "AGENTS dot md, in agent", "the branch origin main", "a commit", ", line 42", "approximately", units such as "seconds", punctuation names), and Spanish-only rules (contractions, "Decisiones pendientes") do not apply. Spanish text is read exactly as today. Whether Supertonic can also speak English text with its English pronunciation (`lang`) is measured first and changed only after the owner listens. Owner chose Spanish pronunciation for English text too (L57): `lang` stays "es".
- S8 — Auto-read switch (L60). Owner (verbatim, L59): "ahora, podemos tener algo así como un "switch" para leer automáticamente?"; choices "/read-auto on|off por sesión (recomendado)" and, for what it reads (verbatim): "elegible pero con la full por defecto, es decir, cuando no indiquemos el valor que sea full por defecto, solo si se indica las questions hacerlo." → per session, off at session start (S1's default=false holds). `/read-auto on` reads every new reply in full; `/read-auto questions` reads only its closing questions section (the "Needs your decision" heading or bold-only line and what follows it, cleaned as usual), and nothing when a reply has none; `/read-auto off` turns it off; `/read-auto` with no argument toggles (off → on in full; any on → off). Messages: "Auto-read on: full replies.", "Auto-read on: questions only.", "Auto-read off."; anything else warns "Use /read-auto on, questions or off." and changes nothing. When the agent's turn ends with a reply, that reply is read exactly as `/read` would (same output choice on first use, voice, speed, footer, Esc, `/read-stop`, one reading per machine). Replies of earlier turns are never read retroactively. Queue (L102, owner, verbatim: "un tema que también me llama la antención es eso de que los audios se pisan, ahora mismo creo que pusimos eso de que los audios se corten, pero esto está bien? creo que podría ser muy molesto si hay muchos audios, por ejemplo: promp -> r1 -> se lee -> r2 aparece y cancela el audio anterior mientras seguía leyecdo."; choices "Encolar (recomendado)" and "Esperar a que termine (recomendado)"): auto-read never interrupts. A reply due for auto-read while a reading plays, in this session or in any other session or process on the machine (S1's lock), waits and is read when the machine is free, replies of one session in order. Explicit actions still win: a manual `/read` and `/read-stop` stop the reading playing, as today, and drop every auto-read waiting on the machine at that moment. Since S15 (L135) Esc pauses instead and keeps the waiting readings. `/read-auto off` and the session's end drop that session's waiting replies. A reading stopped by another session clears its status quietly, as today. Ask before cutting (L105, owner, verbatim: "podemos preguntar? algo como: cortar o encolar?"; choice "Para `s` en Alt+R y para /read (recomendado)"): when a manual `/read` (any form) or a `reply-reader:read` request (Alt+R `s`) comes while a reading plays anywhere on the machine, the reader asks first, with the title "Something is being read." and two choices, "Stop it and read now" (today's behaviour: stop, drop the waiting auto-reads, read) and "Read after it" (the request waits like an auto-read, after this session's waiting replies, and is dropped by the same explicit actions). Dismissing the question changes nothing: nothing stops, nothing plays, no message. With nothing playing, or without a UI, it reads at once as today. `/read-stop` and Esc never ask. The standalone `reply-reader` command (L105, choice "Vaciar la cola, como un /read (recomendado)") also drops the auto-reads waiting in Pi sessions when it starts reading, as a manual `/read` does; it never asks. Timing (L127, owner choice "Apenas termina cada respuesta"): each new final reply joins the line as soon as it is stored (on `message_end`, after Pi stores the entry, as pi-reply-thread refreshes its view), even while the agent keeps working; every final reply is read once, in order, none is skipped (T42), and none from before auto-read was turned on or the session started.
- S9 — Read from a section (L60, choice "Leer desde una sección"). `/read <target>#<section>`, where target is a Markdown file, a reply ID, or empty for the latest reply (`/read #instalación`), reads only that section: from the first heading whose text matches, up to the next heading of the same or a higher level (L61). Adding the word `rest` after it (`/read README.md#install rest`) reads from that heading to the end instead. Matching ignores case, accents, punctuation and leading numbering, and spaces may be written as `-` (`#install`, `#one-reading-per-machine`, `#Markdown files`). An exact match wins over a prefix match; a prefix match is accepted when it is the only one. No match warns `No section "<section>" in <name>.` and nothing plays. Without `#` everything works as before.
- S10 — Read from pi-reply-thread's Alt+R view (L78). Owner (verbatim, L77): "podemos integrarlo con el otro plugin que hice sobre el de las respuestas? creo que era thread o algo así, lo de acceder con alt+r"; choices "Tecla en Alt+R + handshake (recomendado)", key "s (speak)", "Solo esa pregunta (recomendado)", and for the other repo (verbatim): "tengo una sesión abierta ahora mismo, puedes coordinar con ella?". No package depends on the other; they talk over Pi's shared event bus (`pi.events`). Contract v1 (agreed with the pi-reply-thread session, L79): `reply-reader:read` with `{ v: 1, id: string, text: string }` asks the reader to read `text` (Markdown) aloud, naming `id` in the footer and messages, exactly like `/read` (cleanup, language, output choice on first use, voice, speed, Esc, `/read-stop`, one reading per machine); an invalid payload is ignored. Presence: `reply-reader:ping` `{ v: 1 }` from the view is answered with `reply-reader:ready` `{ v: 1 }` synchronously inside the ping handler, before any await (the bus is a synchronous EventEmitter and the view reads its flag in the same call); the reader also emits `reply-reader:ready` at session start. In Alt+R, `s` reads the selected reply (Replies tab and the reply viewer) or only the selected question's text (Pending and Answered tabs); the key and its hint appear only when the reader answered.
- S5 — Two modes. Owner (verbatim, L20): "estamos suponiendo que el audio sea ese momento, o me equivoco? si es así podemos tener dos modos? uno este rápido y otro de mejor calidad?" → fast = S3. Quality = the GPU engine chosen in lab-ai's bake-off, reached over the network; it may take longer ("preparando audio…"). When it is unreachable, the reader says so and offers fast. The contract follows lab-ai's Fase 5 (L16).
- S4 — Where it sounds.
